# Resource reference coverage

This is an audit map for the current working-tree Core, not a promise about a published package. Read the linked DSL page and `packages/core/src/index.d.ts` alongside `packages/core/src/registry.mjs`; behavioral contracts are in `docs/VIEWSTEM-SPEC.md` and `docs/spec/`. `scripts/core-docs-inventory.mjs` maps exported types to their documentation owners. The links below use the route suffix shared by `src/content/docs/docs/` and `src/content/docs/ko/docs/`.

“DSL fixture” means the exact fenced JSON in both languages is read by `scripts/verify-dsl-docs.mjs`. “Lesson” means the corresponding interactive example in `src/examples/definitions.ts` and catalog; `verify-site-previews.mjs` opens all lessons, but exercises only a subset of their interactions. Presence in this map is not proof that every behavior or cross-product combination was tested.

| Contract / source | Fields and variants to audit | DSL owner | Example and verification | Runtime-only or remaining boundary |
| --- | --- | --- | --- | --- |
| Resource / `index.d.ts`, `registry.mjs` | `kind`, `id`, `name`, `spec`; seven kinds; reference vs inline; batch registration | `dsl/resources/` | `resources.json` DSL fixture | dependency and cycle checks depend on the registry contents |
| View / `index.d.ts`, `registry.mjs` | `render`, `ports`, `states`, `queries`, `queryDefaults`, `reactions`; no public `slots`/`events` | `dsl/view-and-component/` | `view-resource.json`; lessons first-view, view-inputs | rendering requires registered implementations |
| Component / same | View fields plus `slots`, `events`; code contract vs declarative `render` | `dsl/view-and-component/` | `component-resource.json`; reusable-component, inline-component, component-state, forward-slot, component-event | code implementation and lifecycle are host/renderer responsibilities |
| ComponentNode / same | `id`, `componentRef`/`component`, `inputs`, `slots`, `on`, `when`, `repeat.items/as/key`; Action call vs `emit`/`payload` | `dsl/view-and-component/` | `repeated-view.json`; conditions, repeat, event-payload, component-event, forward-slot | slot scope, repeated identity and event payload depend on execution context |
| State / `index.d.ts`, `registry.mjs`, `state.mjs` | `State` and `Derived`, `schema`/`typeRef`, `initial`, `variableRef`/`variable`, `inputs`; Reaction `watch`, `target`, `value` | `dsl/state-and-ports/` | `derived-view.json`; state, derived, state-reaction | dependency ordering and transaction precedence are runtime behavior |

| Type / `index.d.ts`, `schema-profile.mjs`, `schema.mjs` | `schema`, `typeRef`; supported JSON Schema keywords, local `$ref`, native `set`, `map`, `date`, `time`, `datetime` | `dsl/types/` | `type-resource.json`, `project-type.json`; shared-type | only a subset of JSON Schema 2020-12 is supported; native values are not JSON definitions |
| Values / `expression-syntax.mjs`, `expressions.mjs`, `http/expressions.mjs` | literals, `@path`, `@call`, `args`, escaped keys, evaluation roots, concat/formatString and registered functions | `dsl/values/`, `dsl/datasources/`, `core/cel/` | `format-title.json`, `login-query.json`; value-call, event-payload | available roots and functions depend on evaluation location; HTTP has a separate evaluator |

The seven structural JSON Schemas use [a shared source](src/lib/resource-schemas.mjs) and appear inline and as standalone downloads. The `Type` resource's own `schema` field describes values. Core also checks registry references, expressions, authorization, and runtime behavior.
