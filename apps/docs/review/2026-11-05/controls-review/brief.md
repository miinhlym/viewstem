# 문서 컴포넌트 옵션 편집 제안 — 검토 대상

상태: 사용자 아이디어에 대한 검토. 구현 승인이나 확정 계약이 아니다.

## 사용자 목적
라이브러리 문서에서 지원 컴포넌트를 찾고, 실제 UI를 조작하고, 이를 구성하는 JSON을 이해한다. 제안은 Storybook처럼 옵션을 바꾸면 JSON이 바뀌고 그 JSON에 따라 미리보기 컴포넌트가 반응하도록 하는 것이다. 모든 옵션 노출, JSON 직접 편집, Storybook 의존성 도입 여부는 아직 정해지지 않았다.

## 확인한 현재 구조
- Viewstem은 JSON 형태의 ViewSpec으로 컴포넌트 트리·입력·State 초기값·이벤트 Action을 선언하고 공개 렌더러로 실행한다.
- 문서 좌측 메뉴에 지원 계열 66개가 표시된다. 각 계열의 한국어·영어 페이지 총 132개에는 실제 미리보기, 읽기 전용 JSON, JSON 복사, 미리보기 초기화, 앱 등록 코드가 있다.
- 현재 사이트 예제 데이터의 하나의 view가 화면에 표시하는 JSON과 렌더러 입력으로 함께 쓰인다. 옵션 편집 UI는 아직 없다.
- UI 클릭·입력은 렌더러 내부 State를 바꿀 수 있다. 선언 JSON의 State.initial과 실행 중 State 값은 별개다. 입력에는 리터럴뿐 아니라 {'@path':'/states/value'} 같은 참조 표현식이 올 수 있다.
- Tabs, Dialog 같은 계열은 Root/Trigger/Content 등 여러 부품을 조합한다. Sonner는 JSON 외에 호스트가 등록한 Action도 사용한다. 모든 부품이 JSON에 직접 등록되는 것은 아니다.
- 현재 demo runtime은 mount 및 dispose를 제공한다. 새 JSON의 변경분을 적용하는 문서 전용 update 계약은 없다.
- 같은 사이트의 Playground는 JSON 편집·검증·실행 용도다. 문서 옵션에서 Playground로 수정된 JSON을 전달하는 기능은 확인되지 않았다.
- 문서는 본문 읽기, 검색, 한·영 전환, 모바일 메뉴, 밝고 어두운 테마도 지원한다.

## 검토할 대안
A. 현재 실제 미리보기+정적 JSON을 유지하고 다양한 예제를 추가한다.
B. 문서별로 의미 있는 소수 옵션을 편집하며 JSON과 미리보기를 함께 갱신한다.
C. 공개 메타데이터에서 가능한 모든 옵션 편집기를 자동 생성한다.
D. 이 기능을 문서 대신 Playground에 집중한다.

## 확인이 필요한 질문
어떤 대안이 학습에 가장 도움이 되는가? 코드 수정에 비해 조작 UI가 설명을 더 잘하는 사례는 무엇인가? 설정 변경과 실행 상태 변화는 어떻게 구별하는가? 바인딩·조합 부품·호스트 Action은 어떻게 취급하는가? 모바일 공간과 키보드 초점을 해치지 않는가? 복사 JSON이 실제 실행 결과를 재현하는가? 오류·초기화·빠른 연속 변경은 어떻게 보여야 하는가? 전 계열 유지보수 비용에 비해 가치가 있는가?

공식 레퍼런스 관찰: Storybook Args 문서는 JSON 직렬화 가능한 인자 객체를 변경해 컴포넌트를 다시 렌더링하는 방식을 설명한다. shadcn Button 문서는 동작 예제, 코드, usage, variant 예제를 제공한다. 이는 대안 비교 자료이며 Viewstem에도 같은 설계가 맞는다는 증거는 아니다.
