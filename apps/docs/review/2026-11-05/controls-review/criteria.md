# 검토 기준
- 문서 독자가 옵션 → JSON 필드 → 실제 UI의 관계를 설명할 수 있는가.
- 변경 가능한 설정, 실행 중 상태, 참조 표현식, 네이티브 전용 API를 혼동하지 않는가.
- 화면·복사 JSON·실행 입력이 일치하고 초기화/오류/연속 변경이 예측 가능한가.
- 기존 문서의 읽기·검색·한영·테마·모바일·키보드 흐름을 해치지 않는가.
- 기존 공개 API로 구현 가능하며 core 계약을 불필요하게 확장하지 않는가.
- 대표 복합 사례로 검증 가능한 완료 기준과 유지보수 범위가 있는가.
- 원격 서버나 AI 호출이 없는 로컬 문서 기능이다. 근거 없는 QPS/비용 문제를 만들지 말 것.
- 제안의 장점과 가장 강한 반론을 모두 평가하고, 불확실성/결정 필요 사항을 분리할 것.
