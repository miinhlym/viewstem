# 주요 옵션·JSON·실행 UI·상세 설명 연결

2026-11-05. 사용자가 ECharts 조사 결과를 참고한 구현과 한국어·영어·모바일·테마·초기화 확인을 요청했다. [조사](echarts.md)와 [사전 검토](review.md)의 제안 중 아래 범위를 구현했다. 사이트 공개·배포는 하지 않았다.

## 구현 범위

기존 66개 계열의 한·영 132개 실행 예제를 유지하고, Button·Input·Checkbox·Switch·Slider·Tabs·Dialog·Sonner의 한·영 16개 페이지에 언어별 19개 주요 옵션을 추가했다. 모든 공개 필드를 폼으로 자동 생성하지 않는다.

- 옵션에 의미, 대상 JSON 경로, 해당 상세 레퍼런스를 표시한다. 상세 레퍼런스의 해당 필드에서 옵션으로 돌아올 수 있다.
- 하나의 선언 문자열을 코드 표시·복사·실제 렌더러 실행에 사용한다. 변경 필드를 강조하고 JSON 버튼으로 해당 줄을 찾는다. 옵션 입력 중에는 페이지를 자동 스크롤하거나 초점을 이동하지 않는다.
- State 바인딩은 유지하고 초깃값 옵션은 State.initial만 편집한다. 실행 UI에서 클릭하거나 입력한 State는 선언 JSON에 역기록하지 않는다.
- 옵션 변경은 실행 상태를 다시 초기화한다. ‘현재 설정 다시 실행’은 편집한 선언을 유지하고, ‘기본 예제로 되돌리기’는 컨트롤과 선언을 원본으로 복원한다. 원본에 없던 기본값 필드도 다시 제거된다.
- 텍스트·숫자는 180ms 동안 변경을 모으고 한글 조합 중에는 실행하지 않는다. 진행 중 실행은 직렬로 정리하고 최신 요청만 채택한다. 실행 실패 시 기존 미리보기를 비우고 설정·JSON과 복구 안내를 유지한다.
- 작은 화면에서는 옵션을 한 열로 배치한다. 밝게·어둡게·시스템 테마와 모션 축소 설정을 따른다. JSON 직접 편집은 기존 Playground의 역할을 유지한다.

ECharts에서 가져온 것은 작성자가 지정한 필드 조작, 공유 실행 예제, 필드 설명과 코드의 연결이다. ECharts의 거대한 옵션 트리나 setOption 병합 갱신 의미를 옮기지 않았다. core 및 공개 패키지 API 변경과 의존성 추가는 없다.

독립 코드 리뷰에서 JSON을 수정한 뒤 Shiki의 밝은 배경 inline style이 남아 어두운 테마를 해치는 결함을 발견했다. 동적 JSON 표시로 바꿀 때 해당 style을 제거하고, 최종 매트릭스에 실제 계산된 배경색 검사를 추가해 확인했다. API 링크 왕복 시 브라우저의 기본 앵커 이동이 옵션 초점을 덮는 문제도 수정했다.

병렬 클립보드 검사는 브라우저 문맥 간 시스템 클립보드를 공유하므로 해당 구간을 직렬화했다. Sonner 초기화 검사는 퇴장 애니메이션 후 알림이 제거되는지 확인한다. 빌드와 dist 기반 브라우저 검사를 겹쳐 실행해 정적 파일이 비었던 초기 실패는 최종 결과로 사용하지 않았고, 빌드가 끝난 뒤 전체 회귀를 다시 통과했다.

## 검증 범위의 한계

이번 브라우저 실행은 Chromium이다. Firefox·WebKit 및 실제 독자 대상 학습 효과 실험은 하지 않았다. 페이지 수명 검사는 pagehide/pageshow 신호와 단위 테스트이며 실제 브라우저 BFCache 진입 성공을 입증하지 않는다. 기존 setup 예제와 공개 패키지는 마지막 타입 검사 이후 변경되지 않아 해당 근거를 재사용했다. 최종 코드에서 영향받은 docs 타입·빌드·브라우저 검사는 다시 실행했다.
