# 문서 옵션 → JSON → 실제 UI 검토

2026-11-05. **검토 결과는 제한적 도입 권고다. 구현 승인·완료가 아니다.** 현재 전체 컴포넌트 메뉴·실행 예제는 [별도 구현 기록](../component-previews.md)에 있다.

## 결론과 근거

모든 공개 옵션을 폼으로 펼치면 문서가 복잡해지고, 트리·State·Action을 배우는 대신 조작 화면만 익힐 수 있다. 특히 Viewstem은 props의 평면 목록이 아니라 여러 노드와 참조 표현식으로 구성된다. 따라서 문서별로 시각적·동작 차이를 이해하는 데 유용한 주요 옵션을 제공하는 B안을 권한다. 자유로운 JSON 작성·검증은 기존 Playground의 역할로 둔다.

[Storybook Args](https://storybook.js.org/docs/writing-stories/args)는 직렬화 가능한 인자 객체의 변경으로 컴포넌트를 다시 렌더링한다. [ArgTypes](https://storybook.js.org/docs/api/arg-types)는 옵션 종류·허용 값·설명 등을 지정하고 자동 추론을 수동 설정으로 보완하거나 컨트롤을 비활성화할 수 있다. 이를 참고하면 ‘모든 타입을 무조건 편집기로 노출’하는 것이 Storybook식 경험의 필수 요건은 아니다. [shadcn Button](https://ui.shadcn.com/docs/components/base/button)은 실제 예제와 코드, usage 및 variant 예제를 함께 제공한다. 이 방식은 옵션 편집이 없어도 비교 학습이 가능한 대안이다. 위 공식 자료는 패턴의 근거이며 Viewstem 독자의 학습 효과를 입증하지는 않는다. Controls 안내 페이지는 조회가 실패해 해당 페이지 자체를 근거로 삼지 않았다.

## 독립 검토 방식

EGM의 Comprehension 및 Design Critic 페르소나를 `fork_turns: none`으로 각각 실행했다. 두 리뷰어 모두 [검토 대상](brief.md)과 [기준](criteria.md)을 읽고 완료했다. Design Critic는 ComponentDemo.astro, component-demo-runtime.ts, component-demo-setup.ts, component-demos.mjs도 전문을 읽었다. 리뷰어는 파일을 수정하거나 대화 이력·메모리를 조회하지 않았다.

이는 사용자가 요청한 아이디어에 대한 **범위를 한정한 EGM 페르소나 검토**다. egm-brainstorm의 다회 질문·준비 승인 절차나 egm-review의 전체 5단계·반복 수렴을 수행했다고 주장하지 않는다. 대화 맥락만 분리했고 호스트 지침 파일 제외는 검증하지 않았다. 브라우저 학습 실험이나 옵션 편집 구현 검증은 하지 않았다.

## 주요 지적과 권고 처리

| 지적 | 관찰한 예와 의미 | 권고 |
|---|---|---|
| Major: 폼이 JSON 학습을 가릴 수 있음 | 크기를 바꿔 UI만 달라지면 어느 필드를 작성하는지 알 수 없음 | 옵션에 해당 JSON 필드 이름을 표시하고 변경 부분을 찾기 쉽게 한다. 자동 페이지 스크롤이나 초점 이동은 하지 않는다. |
| Major: 설정과 실행 상태 혼동 | Input 입력 후 disabled 변경으로 재마운트하면 입력값이 사라짐. Tabs.value는 State 참조임 | 첫 버전은 선언 설정만 편집한다. 초기값 옵션은 State.initial을 변경하고 참조를 유지한다. 재실행 시 입력 상태가 초기화됨을 옵션 영역에 설명한다. |
| Major: JSON·복사·실행 버전 불일치 | 현재는 고정 source와 서버 코드라 일치하지만 일부만 갱신하면 낡은 값을 복사·실행할 수 있음 | 하나의 설정 스냅샷에서 표시·복사·실행 입력을 파생하고 적용 중/실패 상태를 구별한다. |
| Major: 연속 실행 수명 관리 | 기존 generation 검사는 늦은 결과 채택을 막지만 진행 중 mount를 취소하지 않음. Sonner 정리는 전역 ID를 사용함 | 최신 요청만 남기는 직렬 재실행을 설계한다. 텍스트는 한글 조합 중 실행하지 않고 짧게 변경을 모은다. 종료한 인스턴스가 새 미리보기를 정리하지 않게 한다. |
| Major: 타입만으로 구조 관계 생성 불가 | OTP 길이와 Slot, Select items와 자식, Tabs Trigger/Content/초기값이 연결됨 | 작성자가 허용 옵션과 변경 규칙을 지정한다. 배열 위치나 순회 순번 ID에 의존하는 임의 패치 대신 안정적인 생성 규칙을 사용한다. |
| Major: JSON 단독 재현의 한계 | Sonner는 호스트 Action 등록이 필요함. 현재 실행 상태가 초기 선언과 다름 | 복사 대상은 ‘현재 설정의 초기 실행 정의’로 명시한다. setup 코드를 유지하고 호스트 Action·계열·트리 구조 편집은 첫 범위에서 제외한다. |
| Major: 모바일·키보드 흐름 악화 | 옵션·미리보기·긴 JSON의 병렬 배치와 재실행 초점 손실 | 작은 화면에서는 옵션과 미리보기, JSON을 세로로 배치한다. 컨트롤 DOM과 초점을 유지하고 코드 변경 알림은 과도하게 읽히지 않게 한다. |
| Nit: 학습 효과 근거 부족 | 66개 페이지에 동일 패널 추가는 교육 효과의 증거가 아님 | 대표 사례에서 정적 예제와 옵션 편집을 비교하고 독자가 변경 필드와 영향을 설명할 수 있는지 확인한다. |

두 리뷰어 모두 B를 권고했고 C의 전면 자동 생성은 추천하지 않았다. 가장 강한 반론은 **문서가 두 번째 Playground가 되며 옵션 정의라는 유지보수 계층만 늘어날 수 있다는 것**이다. 이 반론은 유효하다. 따라서 시각적 차이나 바인딩의 의미를 더 잘 설명하지 못하는 옵션·계열에는 편집기를 추가하지 않는 것이 기준이다.

## 권장 화면과 동작 — 아직 제안

문서 제목·간단한 설명 다음에 미리보기와 주요 옵션을 가까이 두고, 그 아래 전체 View JSON을 둔다. Button은 `text`, `variant`, `size`, `disabled` 정도로 시작할 수 있다. Tabs는 ‘처음 선택된 탭’과 비활성 여부처럼 의미가 명확한 조작을 제공한다. `value`라는 라벨로 실행 상태와 초기값을 뭉뚱그리지 않는다. 긴 HTML/ARIA 입력 계약은 기존 상세 레퍼런스에 유지한다.

옵션 변경 → 새 선언 스냅샷 → JSON 표시/복사 → 같은 스냅샷으로 재실행 흐름을 사용한다. 실행 중 UI 클릭은 선언 JSON에 자동 역반영하지 않는다. 바인딩 입력은 참조를 그대로 두고 작성자가 정한 초기값만 변경한다. ‘현재 설정 다시 실행’과 ‘기본 예제로 되돌리기’를 구별한다.

첫 구현을 진행한다면 실패한 설정과 낡은 화면이 함께 정상처럼 보이지 않도록 **오류 때 미리보기를 비우고 실패 필드·복구 방법을 표시**하는 단순한 정책을 권한다. 표시·복사는 현재 설정을 유지하되 실행 성공 여부가 분명해야 한다. 마지막 성공 결과를 유지하는 방식도 가능하지만 별도 버전 표시가 필요해 첫 범위에는 부담이다. 유효하지 않은 숫자 입력 등은 적용 전에 해당 컨트롤에서 설명한다.

모바일에서는 강제 3열을 쓰지 않는다. 초점은 조작한 옵션에 유지한다. 코드 변경 부분은 잠깐 색으로 표시할 수 있지만 본문을 흔들거나 자동 스크롤하지 않는다. reduced-motion에서는 효과를 줄인다. 이 경험에 Storybook 패키지 도입이나 core 계약 확장이 필요한 근거는 현재 없다.

## 대표 범위와 구현 후 확인할 기준

1. Button: 리터럴 옵션과 JSON 필드의 연결, 기본값 생략/false 구별.
2. Input: 한글 조합 입력, State 참조 보존, 초기값 변경과 실행 입력 구별.
3. Tabs 또는 Dialog: 여러 부품 연결과 초기 상태를 유지하는 변경.
4. Sonner: 호스트 Action 경계, 빠른 재실행과 늦은 dispose의 간섭 여부. 호스트 Action 자체는 편집하지 않는다.

각 사례에서 최종 옵션·표시 JSON·복사 JSON·실행 입력이 일치해야 한다. 지연 로딩 중 연속 변경, 실패 후 복구, 페이지 이탈, 다시 실행과 기본 예제 복원을 검사한다. 한·영·양 테마·320px·키보드·한글 IME도 확인한다. 복사한 JSON과 setup은 별도 실행에서 동일한 초기 동작을 재현해야 한다.

정적 예제(A)와 주요 옵션(B)을 비교해 독자가 ‘어느 JSON 필드를 바꾸었고 무엇이 달라지는지’를 설명하도록 한다. 아직 실제 독자 실험·렌더 비용 측정·공개 메타데이터 관계 표현력 검증은 없다. 이 결과를 보기 전에는 66개 계열 전체에 동일 수준의 편집기를 제공하겠다고 확정하지 않는다.
