# 문서 사이드바 클릭 시 글자 이동 수정

2026-11-06. 사용자가 페이지 전환 때 좌측 사이드바 글자가 약간 움직인다고 보고했다.

후속 확인에서 사용자가 지적한 단어 간격 변화는 아래 누름 효과와 다른 문제임을 확인했다. 실제 Chrome에서 재현한 웹폰트 재등록과 최종 수정은 [font-navigation.md](font-navigation.md)를 따른다. 이 기록은 당시 별도로 발견한 클릭 효과·검색 단축키 이동의 검사 결과로 유지한다.

## 재현과 원인

클릭 전후의 실제 텍스트 Range 좌표와 계산된 폰트를 비교했다. Badge 링크의 y 좌표가 721.03125 → 722.03125 → 721.03125px로 바뀌었지만 폰트·글자 폭·스크롤 값은 동일했다. 공식 Nova Button의 `active:not-aria-[haspopup]:translate-y-px` 눌림 효과가 탐색 메뉴에도 적용된 결과였다. 그룹 버튼도 동일했다. 폰트 다운로드나 교체가 이번에 재현한 1px 이동의 원인은 아니다.

`verify-sidebar-text.mjs`를 수정 전 실행했을 때 한영 × 밝음·어둠 × 375·1024·1440px의 12개 조합이 모두 같은 위치 차이로 실패했다. [수정 전 결과](sidebar-text/before.json)

기존 폰트 검사에서도 별도 작은 layout shift를 발견했다. Search의 단축키가 hydration 시 `Ctrl K`에서 Mac의 `⌘K`로 바뀌면서 표시 폭이 48px에서 24px로 줄었다. [기존 검사 실패](sidebar-text/font-before.txt)

## 수정

- `SidebarNavigation.svelte`의 링크·그룹 버튼 조합에서 눌림 이동만 `translate-y-0`으로 덮어쓴다. 공식 Button 원본 파일, 폰트, 현재 메뉴의 굵기·배경, hover/focus 표현과 다른 동작 버튼의 피드백은 유지한다. 모바일 문서 메뉴도 같은 조합을 사용한다.
- `Search.svelte`는 두 운영체제 단축키를 같은 grid 칸에 배치하고 해당 표기만 보이게 한다. 처음부터 필요한 공간을 확보하고, 플랫폼 감지로 표시가 바뀌어도 위치가 이동하지 않는다. 검색 실행과 키보드 처리는 변경하지 않았다.
- 사용자 화면을 숨기거나 폰트 로딩을 JavaScript로 기다리게 하지 않았다. 폰트 로딩 정책과 파일도 변경하지 않았다.

## 검증

- 개발 서버에서 새 회귀 검사 12/12 통과. 링크·그룹 버튼의 누름/해제 전후 위치·폭·폰트가 동일했고, 데스크톱에서는 실제 링크 이동 후 좌표·스크롤·현재 메뉴를 확인했다. 모바일에서는 문서 Sheet를 연 뒤 검사했다. [결과](sidebar-text/dev.json)
- 기존 폰트 검사 24조건 통과. 첫 방문·캐시 재방문·600ms 폰트 지연·폰트 다운로드 실패를 포함한다. 문서 12조건은 최초 표시 이후 측정한 본문·제목·코드·헤더 위치 변화와 layout-shift가 모두 0이다. 홈의 의도된 진입 애니메이션까지 없다고 주장하지 않는다. [결과](sidebar-text/fonts-dev.json)
- 프로덕션 빌드 통과 후 같은 위치 검사 12/12, 기존 사이드바 복원 10/10, 폰트 검사 24조건 모두 통과했다. 사이드바 복원에는 hydration 350ms 지연·새로고침·뒤로 가기·저장소 차단·모바일 분리가 포함된다. [위치](sidebar-text/production.json), [스크롤](sidebar-text/scroll.json), [폰트](sidebar-text/fonts-production.json), [빌드](sidebar-text/build.txt)
- 공식 원본 소스 115개 해시 검사도 통과했다. 개발 서버 4321을 재시작하고 실제 메뉴 이동·검색 단축키·Escape 동작을 확인했다.
- 공식 Svelte 분석 오류 0. Search의 비동기 검색 effect에 대한 일반 제안은 이번 변경과 무관하며, 기존 취소·경쟁 처리 구조를 보존했다.
- 문서 앱 Astro·Svelte 타입 검사 오류·경고 0. [로그](sidebar-text/typecheck.txt)

브라우저 검증 범위는 Chromium이다. 선택 메뉴의 정상적인 강조 변경과 Sheet 진입 애니메이션은 유지한다.
