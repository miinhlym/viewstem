## 검토 대상

상세 페이지를 열자마자 해당 컴포넌트를 조작해 보고, 원하는 변형의 View JSON을 찾아 복사할 수 있어야 한다. 현재 두 패키지의 상세 문서는 언어별로 같은 대표 JSON 하나를 미리보기·JSON 탭에서 보여 준다. 탭을 바꿔도 입력·선택 등 실행 상태가 유지된다. [현재 결정 D142](../../../../../docs/history/decision-register.md#a-현재-채택한-결정)

shadcn-svelte Button 페이지는 첫 화면에 외곽선 버튼과 아이콘 버튼을 제시한다. 아래에서 크기를 한 줄로 비교하고, 외곽선·보조·위험 스타일과 로딩·버튼 그룹·링크 사용법을 목차에서 찾아갈 수 있는 예제로 설명한다. 로딩과 버튼 그룹은 입력값 외에도 자식 컴포넌트나 구조가 바뀐다. [shadcn-svelte Button](https://www.shadcn-svelte.com/docs/components/button)

## 대안

| 구성 | 가장 적합한 일 | 검토할 비용 |
| --- | --- | --- |
| 상단 기본 예제, 하단 변형 예제 | 여러 모양을 한눈에 비교하고 특정 사례를 링크로 공유한다. 복합 예제는 해당 조합의 JSON을 그대로 제공한다. | 변형마다 큰 미리보기를 두면 모바일에서 페이지가 길어지고, 처음부터 전부 렌더링하면 초기 실행 비용이 늘어난다. |
| 한 미리보기에서 속성 편집 | 같은 버튼에서 크기와 스타일을 섞어 보거나 특정 값을 시험한다. | 다른 모양을 비교하려면 선택을 반복한다. 슬롯·자식·이벤트가 달라지는 사례는 편집기의 옵션 규칙이 늘어난다. 표시·실행·복사하는 JSON을 같은 설정에 맞추고, 옵션 변경 시 입력값과 열린 UI의 상태 정책도 정해야 한다. |
| 한 미리보기에서 미리 정의한 예제를 선택 | 정해진 변형마다 완성된 JSON을 주면서 실행 영역을 하나로 유지한다. | 같은 화면에서 여러 변형을 비교하기 어렵다. 선택 항목 이름과 주소로 구체적인 예제를 찾을 수 있어야 한다. |

## 검토에 부칠 가설

상단에는 가장 작은 기본 예제와 미리보기·JSON 탭을 둔다. 하단에서는 같은 구조의 스타일과 크기를 짧은 한 줄 또는 그리드로 묶고, 로딩처럼 슬롯 구성이 달라질 때는 독립된 예제로 보여 준다. Button에선 스타일·크기·로딩으로 시작할 수 있다. 기존 소스에 세 묶음의 JSON이 정의돼 있어 이 가설을 구체적으로 검토할 수 있다. [Button 예제 정의](../../../src/examples/component-reference-demos.mjs#L174)

하단 예제는 목차 링크로 바로 찾을 수 있게 하고, 조합 예제에는 해당 JSON을 함께 둔다. 두 렌더러는 언어별 같은 JSON을 공유한다. 모든 조합을 문서에 나열할지, 복합 예제가 몇 개면 충분한지, 자유 편집이 필요한 사용 사례를 Playground로 연결할 수 있는지는 검토 대상이다.

## 판단 기준

- 처음 방문한 사람이 옵션을 건드리기 전에 기본 사용법을 실행하고 JSON을 복사할 수 있는가.
- 스타일·크기 비교와 슬롯·이벤트 조합 학습에 각각 맞는가.
- 두 렌더러에서 같은 예제 주소와 JSON을 검증할 수 있는가.
- 모바일에서 변형을 쉽게 찾을 수 있는가. 하단 예제가 늘어날 때 초기 로드 비용을 실제로 측정할 수 있는가.
- Button뿐 아니라 Dialog의 닫기 버튼 옵션과 Data Table의 열·행 구성에도 같은 판단 기준이 성립하는가.

## Goldfish 검토 종합

독립 리뷰 7개를 완료했다. 설계, 코드 재사용, 범위, 독자 이해, 구현 준비, 문서 구조, 대안 설계의 관점에서 확인했다.

**권고안** 문서의 기본 구조는 상단 기본 예제와 하단 변형이다. 문서에서 가장 자주 지원해야 할 과업을 기본 사용법 확인, 지원되는 변형 발견, 재현 가능한 JSON 복사로 두었다. 사용자가 값의 조합을 직접 탐색하는 과업에는 단일 속성 편집이 더 적합하다. 큰 상태 기반 예제를 하나씩 실행하는 과업에는 단일 미리보기의 완성 예제 선택이 유력하다.

| 같은 사용자 과업 | 상단 기본 + 하단 변형 | 한 미리보기에서 변형 |
| --- | --- | --- |
| 기본 예제 조작과 복사 | 상단에서 바로 가능 | 기본 상태로 열면 동일 |
| Button 스타일·크기 비교 | 같은 화면에서 차이를 확인 | 순서대로 바꾸며 이전 결과를 기억해야 함 |
| 특정 구성 찾기와 JSON 복사 | 이름과 목차에서 찾아 해당 View JSON 복사 | 선택 목록에 이름이 보여야 하며 선택·미리보기·복사가 함께 바뀌어야 함 |
| Dialog·Data Table 시나리오 실행 | 조작 흐름과 설명을 각 사례에 붙일 수 있으나 화면과 코드가 길어짐 | 같은 자리를 재사용해 하나씩 실행하기 편함. 전환 시 초기화 범위를 정해야 함 |
| 임의의 속성 조합 탐색 | 준비한 예제 범위에서 비교 | 실시간 속성 편집에 유리. 슬롯·이벤트 조합까지 지원하면 편집 규칙과 검증 범위가 늘어남 |

### 권고안을 적용하는 기준

- **Button**은 상단에 최소 기본 버튼과 미리보기·JSON 탭을 둔다. 하단에서 스타일과 크기를 각각 한 묶음으로 보여 주고, Spinner를 포함하는 로딩을 독립 예제로 둔다. 스타일 여섯 개가 하나의 View일 때 복사 이름도 ‘스타일 비교 예제 JSON’으로 표시한다. 개별 버튼을 복사하는 기능은 별도의 사용 요구로 판단한다. [현재 Button JSON](../../../src/examples/component-reference-demos.mjs#L174)
- **Dialog**에서 닫기 아이콘을 비교한다면 푸터 버튼을 고정해 해당 옵션의 효과만 확인한다. 현재 대안은 닫기 아이콘과 Cancel 버튼을 함께 바꾼다. **Data Table**은 열과 행, 검색·정렬을 한 사례씩 보므로 표 여러 개를 자동으로 나열할 이유가 약하다. 독립적으로 설명할 사례가 생기면 예제 제목과 JSON을 연결하고, 실행 화면이 크면 선택한 한 사례만 열어 볼 수 있다. [현재 Dialog와 Data Table JSON](../../../src/examples/component-reference-demos.mjs#L288)
- 변형이 설명할 사용 사례가 있는 계열에만 하단을 추가한다. 각 제목은 목차와 모바일에서 바로 찾을 수 있게 하며, 두 패키지와 한·영 페이지에서 동일한 예제 키를 사용한다. 복사·표시·실행은 같은 언어에서 같은 초기 JSON을 사용하고, 기본 예제의 탭 전환과 기존 링크 동작을 보존한다. 현재 페이지는 첫 항목과 고정 ID를 사용하므로 전체 예제 UI를 반복하면 ID가 겹친다. [카탈로그](../../../src/examples/component-reference-demos.mjs#L695) · [현재 미리보기](../../../src/components/ComponentDemo.astro#L23) · [목차 등록](../../../src/lib/docs-route.ts#L21)
- 자유 편집은 별도 사용 과업으로 다룬다. 기존 Playground는 Button·Card·Switch만 등록하므로 Spinner나 Dialog, Data Table을 포함한 예제까지 즉시 옮겨 실행할 수 있다는 가정을 두지 않는다. [Playground 등록 코드](../../../src/components/playground-renderer.ts#L1)

### 검증할 가설

Button·Dialog·Data Table을 같은 예제와 복사 단위로 구성해 비교한다. 기본 실행, 변형 찾기·비교, JSON 복사를 한·영 모바일과 데스크톱에서 시험한다. 성공 여부, 복사 오류, 소요 시간과 조작 횟수를 기록한다. 성능은 현행 D142를 기준으로 첫 예제 조작 가능 시간, 초기 마운트 수, 압축 HTML·JS 전송량을 따로 잰다. 하단 지연 마운트는 실행 비용을 줄일 수 있고, HTML에 실린 JSON의 크기는 별도로 확인해야 한다. 첫 화면에서 하단 실행을 시작하지 않는 것을 검증 조건으로 둔다.

단일 미리보기에서 변형을 선택하는 안이 비교 과업에서 비슷한 성공률과 시간을 보이고, 특정 예제 찾기·복사 또는 초기 로드에서 우세하면 해당 계열에서 그 방식을 채택할 근거가 된다. 이번 결론은 독립 리뷰와 소스 대조에 근거한다. 새 화면의 사용성 테스트와 성능 측정은 아직 수행하지 않았다.
