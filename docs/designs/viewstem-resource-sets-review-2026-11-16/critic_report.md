# EGM 7단계 · 설계·구조·문장 검토

독립 `egm-design`, `egm-structural`, `egm-style` 검토 결과. 리뷰어는 각 페르소나, 해당 표준, [대상 명세](../../spec/12-resource-sets-browser.md) 1–69행과 지정 로컬 맥락을 읽었다. 범위 표기의 행 번호는 별도 문서명을 적은 곳을 제외하면 대상 명세 기준이다.

## 설계

| ID | 심각도 | 발견 및 보완 방향 |
|---|---|---|
| D7-1 | Major | 48–52·58행의 “적용 또는 사용 시”는 A의 적용 후보에 이미 보이는 PlantMap에 구현이 없을 때 적용을 거절하는 경로와 적용을 게시하고 렌더 오류를 내는 경로를 모두 허용한다. 후보에서 확인 가능한 누락과 적용 후 처음 드러나는 누락의 관찰 결과를 정한다. |
| D7-2 | Major | 34–36행. 같은 Node 프로세스에서 별도 Registry를 주입받은 두 호스트가 각자 `PlantMap`을 등록할 때, 프로세스와 호스트 조립 단위 중 무엇을 실행 환경으로 간주하는지에 따라 결과가 달라진다. 저장소의 명시적 소유 경계와 현행 주입 사용처의 이행을 설명한다. |
| D7-3 | Major | 66–69행과 인계 44행. Svelte Layout이 같은 Button 주소·세대를 유지하면서 slot 컨테이너를 `<section>`에서 `<aside>`로 바꾸면 같은 인스턴스를 이동할지 해제 후 새로 만들지 불명확하다. 초기 연결 계약에서 슬롯을 안정적으로 유지하거나, 철회와 재연결의 수명 의미를 정의할 수 있다. |
| D7-4 | Major | 9·25–30·62행. 셋 모듈의 import가 이벤트 구독을 만드는 경우 등록 실패로 구독을 되돌릴 수 없다. 실행 코드의 신뢰와 권한은 호스트의 판단이며, capability 선언과 저장소 게시 원자성의 범위를 명시한다. 현행 코드 Action의 신뢰 모델을 재사용할 수 있다. |
| D7-5 | Nit | 25–27행의 충돌 기준을 상위 정의 식별 계약에 맞춰 `(kind, id)`로 명시한다. |

Svelte 주도, 공통 기반, 전체 렌더러 bridge의 기술적 대안과 초기 조립 전용 등록을 떠난 이유는 연결된 결정 이력에서 추적할 수 있다. [결정 이력](../../history/resource-sets-browser-2026-11-16.md#아키텍처-선택)

## 구조

| ID | 심각도 | 발견 및 보완 방향 |
|---|---|---|
| R7-1 | Major | 25·27행과 인계 45행. 등록 충돌에 `kind`가 포함되는지와 의존 순환의 거절 여부·검출 방식 중 무엇이 미결인지 명세와 인계에서 일치시킨다. |
| R7-2 | Major | 9·62행과 인계 30행. 제삼자 실행 코드와 호스트 capability의 신뢰 경계가 인계의 미결 표에만 있어 본문에서 찾기 어렵다. 본문에서 영향 범위와 미결 항목을 연결한다. |
| R7-3 | Major | 19·62행과 인계 42–48행. 공식 연결자 조합과 렌더러 누락 사례는 있지만 제삼자 연결자나 서비스가 capability를 공급하고 누락을 진단하는 사례는 없다. 수락 조건이나 후속 범위에 연결한다. |
| R7-4 | Nit | 48행의 “확정된 효과” 열에 52행의 미확정 복구도 포함한다. 열 제목을 “보장 범위와 미결 사항” 등으로 바꾼다. |

제목 계층과 표는 일관된다. 첫 문단의 링크를 통해 현행 API, 설계 대안, 수락 기준을 찾을 수 있다.

## 문장

| ID | 심각도 | 발견 및 보완 방향 |
|---|---|---|
| S7-1 | Major | 25–27행. “같은 리소스 ID” 표현은 다른 종류의 정의까지 거절하는 것으로 읽힌다. 같은 `(kind, id)`일 때 충돌한다고 쓰고 다른 종류의 동일 ID는 허용한다고 명시한다. |
| S7-2 | Nit | 19–21행. “Svelte가 DOM 위에서 동작한다는 표현”은 도입되지 않은 표현에 의존한다. Svelte 및 바닐라 DOM 연결자가 공통 브라우저 기반을 사용한다고 바로 설명한다. |
| S7-3 | Nit | 58–60행. “UI 구현을 조용히 누락”의 기준이 모호하다. 소비자가 의도적으로 고른 core 전용 구성과 등록 요청에 포함된 UI 구현이 빠진 경우를 구별한다. |
| S7-4 | Nit | 67행. “하나의 View를 기준으로”는 View 전체가 하나의 인스턴스 ID 범위라는 인상을 줄 수 있다. 한 View 안에서 core 인스턴스 식별·수명 규칙에 따라 자식을 조정한다고 쓴다. |
