# Codex 스킬 확장 비교 실행 계약 — 2026-11-05

사용자는 Claude Code를 준비 상태로 유지하고 Codex의 나머지 시나리오·불필요한 활성화를 비교한 뒤 스킬을 보완하고 배포 준비를 판단하도록 요청했다. 공개 발행은 하지 않는다. 기존 제품·문서 사이트 변경을 보존하며 현재 작업 트리에서 `skills/`와 이 작업의 설계·인계만 변경한다.

## 완료 기준과 범위

[기존 설계](../../design_draft.md#62-행동-평가)의 10개 범주를 아래 11개 과제로 확인한다. 두 비활성화 과제는 같은 Viewstem 의존성이 있는 앱의 무관한 작업이다. 후보의 description이나 본문을 미리 읽으라고 요청하지 않는다.

| 범주 | 과제 ID | 관찰 |
|---|---|---|
| 첫 화면 | first-view | 화면·UI·CSS·정리 |
| 폼 저장·재조회 | form-refresh | 이름을 언급하지 않은 기존 폼 수정, State·Action·Query 연결, 성공 후 refresh·실패 후 값 유지 |
| core 단독 | core-only | Svelte 없는 의존성 트리, NodeNext 타입 검사, 실제 State·Action·dispose |
| 반복 정렬·필터 | repeat | 행별 core State, 안정 key, 살아있는 행의 상태 유지, 제거된 행의 늦은 쓰기 차단 |
| native UI | native | 공개 native Calendar 조합, 가짜 JSON ID 없음 |
| 완료 신호 | completion | resolve된 보고의 queryErrors, Query snapshot, DOM 완료와 paint의 구분 |
| 렌더 실패 | renderer-error | 성공한 State 쓰기 유지, onError 전달, 실패 DOM·정리. 제공 adapter는 수정 금지 |
| 늦은 응답 | late-response | View 교체 후 이전 요청이 현재 화면을 덮어쓰지 않음 |
| 버전·지원 | version-unsupported | 설치 버전·공개 타입·실제 CEL 지원 파일 근거, 미검증 버전 추정 없음 |
| 불필요 활성화 1 | svelte-decoy | 일반 Svelte 색상 변경, Viewstem 본문 읽기·불필요한 변경 없음 |
| 불필요 활성화 2 | other-decoy | Node URL 유틸리티, Viewstem 본문 읽기·불필요한 변경 없음 |

각 과제를 A(대상 스킬 없음)와 B2(초기 실험 최종 후보)에서 3회 비교한다. first-view/native의 유효한 기존 1회씩 4개 결과는 재사용하고 각 2회 추가한다. 나머지 9개 과제는 각 3회씩 새로 수행한다. 총 66개 비교 중 새 모델 실행은 62개다. 최초 폼 실험은 실패·재조회를 포함하지 않았으므로 form-refresh 결과로 재사용하지 않는다.

## 고정 입력과 측정

기존 [초기 결과](../../skills/tests/behavior-results.json)의 세 tarball hash와 외부 초기 앱을 재사용한다. Codex `0.160.0`, `gpt-6.1-terra/high`, 새 ephemeral 세션, 360초·명령 50회 제한을 유지한다. 두 조건의 prompt·초기 코드·의존성·도구는 같고 스킬 설치만 다르다. core-only 준비는 새 임시 앱에서 Svelte 의존성을 제거하고 manifest·lock·설치 트리를 맞춘다.

홀짝 반복에서 두 조건의 시작 순서를 바꾼다. 작업 묶음별 1–2개, 전체 최대 3개 모델 세션이 병행된다. 최초 실행 등록과 각 묶음의 입력은 [계획 JSON](../../skills/tests/extended-plan.json) 및 임시 workspace의 plan 파일에 보존한다. 이는 무작위 실험이 아니며 wall time·캐시·토큰 차이를 인과적 성능 개선으로 해석하지 않는다.

검사기는 유효한 참조 구현과 핵심 실패 사례를 먼저 검사한다. 정답은 평가 앱에 복사하지 않는다. 실제 산출물은 타입·실행·브라우저 검증과 코드 검토를 함께 판정한다. core import가 존재하거나 고정 배열이 맞는 것만으로 State·Action 사용을 인정하지 않는다. DOM 값만 유지되는 결과를 core State 보존으로 계산하지 않는다.

활성화는 실제 SKILL 본문이 성공한 도구 출력에 전달됐는지 확인한다. 파일 경로 목록이나 실패한 읽기는 별도 접근 기록이며 본문 읽기가 아니다. trace와 최종 코드·응답을 함께 검토해 무관한 Viewstem 도입·조언도 확인한다. 다른 개인 스킬은 동일하게 사용 가능하므로 완전히 깨끗한 호스트를 검증한 것으로 표현하지 않는다.

## 수정과 재평가 규칙

원래 실패를 보존한다. 평가기 오류는 스킬 오류와 분리하고, 입력이 같으면 생성 산출물을 수정된 검사기로 재채점한다. 스킬 변경은 B3 등 별도 후보 식별자를 사용하며 해결하려던 실패와 영향을 받는 활성화·동작을 다시 검증한다. 기준선이 이미 성공한 과제에서 후보가 절차만 늘리면 지침을 축소할 근거로 검토한다. 파일 수나 helper 구현 자체를 완료 조건으로 삼지 않는다.

검토 중 발견한 평가기 문제는 별도로 기록한다: 단순 경로 조회의 읽기 오탐, 미완료 결과의 자동 재사용, 채점 프로세스 시간 제한, 실제 존재하지 않는 진단 근거 경로. 완료한 실행의 raw trace·생성 코드는 보존하고 바뀐 판정만 구분한다.

## 배포 판단 경계

Codex의 기능 정확성·적절한 활성화·설치 발견을 각각 판정한다. Claude Code 모델 호출·로그인·설치는 수행하지 않는다. 두 호스트 동시 지원 목표, 다른 발견 경로와 공개 immutable ref의 확인은 별도 조건이다. Codex 실험의 통과가 두 호스트·모든 클라우드·모든 패키지 버전의 배포 준비 완료를 뜻하지 않는다.
