# Viewstem 소비자용 스킬: 최종 EGM 리뷰와 착수 판단

- 날짜: 2026-11-05
- 판정: **조건부 착수 가능 — 얇은 스킬과 초기 비교 실험은 시작할 수 있다. 현재 문서를 전체 구현의 확정 인계서로 사용하는 것은 아직 이르다.**
- 대상: [현재 초안](../../../design_draft.md)의 [267행 고정 snapshot](review_input_snapshot.md), SHA-256 `93d6a46b61ed990fb2385b3e6565950d90033bdeeb72015406f2f8a1820b6967`.
- 결과: 5단계, 9개 fresh-context 관점 완료. 원시 **Blocker 0 / Major 6 / Nit 9**; 중복 통합 **Blocker 0 / Major 4 / Nit 3**.
- 상태: 리뷰 대상 원문은 수정하지 않았다. 아래는 검토 결과와 수정 권고다. 스킬·helper 구현, 설치, 배포, 행동 평가는 수행하지 않았다.

## 1. 먼저 해결할 사항

### F1 · Major — 조건부 조회 도구를 필수 구현 단계로 적은 모순

[초안 237행](../../../design_draft.md#7-구현-단계와-작업-경계)은 helper와 테스트를 필수 2단계로 만들지만, 211행은 C 조건에서 UI 조회 실패·반복 비용을 관찰한 경우에만 추가하도록 한다. 필요성 평가보다 구현이 먼저 일어날 수 있다.

**수정:** 1단계에 초기 A→B→필요한 C 비교를 연결한다. 2단계는 그 결과가 도입 조건을 충족할 때 실행하고, 미충족이면 근거를 남겨 생략한다. 기존 §4의 설계는 조건이 성립했을 때 적용한다. **helper 착수 전 필수**, 얇은 스킬 작성은 막지 않는다.

### F2 · Major — 설치·발견·교체 경로가 아직 구현자의 선택으로 남음

44–46, 182–190, 202, 239–241행은 두 integration 파일과 검증을 요구하지만 실제 경로를 고정하지 않는다. 로컬 폴더와 계정·클라우드 경로의 발견 범위는 다르며, 현재 설치 도구와 최신 호스트 문서의 경로도 같은 것으로 가정할 수 없다. [Claude Code 공식 설치·발견 문서](https://code.claude.com/docs/en/skills), [OpenAI 공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)

**수정:** 각 integration에 `호스트/세션 유형 → 설치 수단·목적지 → 발견/호출 확인 → 상대 참조·Node 실행 → revision 확인 → 교체/되돌리기` 표를 고정한다. 로컬/클라우드는 배제 기준이 아니라 실제 설치 경로의 검증 차원이다. 기능이 같은 환경마다 모든 행동 평가를 반복할 필요는 없으나, 다른 발견 경로의 검증을 로컬 결과로 대체해서는 안 된다. **호스트 통합 구현·지원 완료 판정 전 필수**다. 특정 클라우드 제품을 새로 지원하기로 결정했다는 뜻은 아니다.

### F3 · Major — version 있는 helper 출력의 경계값이 미정

127, 137–143, 153–162, 237행에는 outputVersion과 정보 목록이 있지만 네 명령의 result 형태, 마지막/빈/범위 밖 페이지, UTF-8 한도의 계산 대상과 초과 오류의 필수 정보가 완결되지 않았다.

**수정:** 네 성공 결과와 주요 오류의 고정 JSON 예시를 추가한다. `offset >= total` 처리, 종료 시 nextOffset, 한도 계산의 직렬화/개행 포함 여부를 정하고 독립 기대값으로 테스트한다. 별도 스키마 라이브러리를 추가할 필요는 없다. **helper 착수 전 필수**이며 초기 문서 스킬 실험의 조건은 아니다.

### F4 · Major — 독립 소비 검증을 실행할 구성이 미정

198–202, 238–241행의 소비 검증 목적은 명확하지만 실행 입력, fixture와 명령이 부족하다. 현재 core 소비 검사는 NodeNext, UI 소비 검사는 Bundler 타입 검사와 Svelte compiler·브라우저 조건을 사용한다. UI의 알려진 upstream 선언 제한도 있다. 기존 검사를 그대로 복사하면 저장소 fixture가 스킬 예제의 누락을 가릴 수 있다. [구체 코드 근거](stage9_codebase.md)

**수정:** `consumer.mjs`가 받는 tarball/skill 경로, 외부 fixture 생성 위치, core와 Svelte/UI의 실행 명령·타입 검사·브라우저 origin·종료 기준을 고정한다. 검증 대상 예제는 배포 스킬에서 가져온다. 관리용 테스트 runner가 사용할 기존 개발 도구와 소비 에이전트가 읽을 수 있는 자료를 구별한다. 기존 테스트의 설정은 검증한 버전에 한해 재사용하며, 소비 앱의 설정을 무조건 바꾸는 지침으로 만들지 않는다. **독립 소비 검증 구현·통과 주장 전 필수**다.

## 3. 유지할 설계와 외부 사례의 의미

**한 개의 공통 `viewstem` 스킬, 필요한 참조만 읽는 구조, 호스트 차이만 분리하는 방향은 유지한다.** 최초 View와 폼은 여러 패키지를 함께 사용한다. 패키지마다 스킬을 나누거나 별도 MCP·원격 조회 계층을 만들 근거는 이번 검토에서 발견되지 않았다.

공식 Agent Skills 지침은 응집된 작업 범위, 비자명한 지식, 참조를 읽을 조건, 실제 작업 결과로 줄이고 보강하는 방식을 권한다. 현재 설계는 이 방향에 맞는다. [공식 작성 지침](https://agentskills.io/skill-creation/best-practices)

Vercel·Supabase는 작은 진입점에서 개별 규칙 자료로 이동하고, Anthropic은 기준선 비교를, Expo는 자동 선택과 결과 품질을 나눠 평가하는 절차를 제공한다. 이를 참고하되 그들의 큰 규칙집·전용 플러그인/기기 harness를 그대로 도입하지 않는다. 해당 스킬들의 공개 설치 집계는 선정 근거이며 품질 보증은 아니다. 커밋에 고정한 원문, 구체 비교와 수치의 한계는 [조사 보고서](research_report.md)에 있다.

지원 JSON의 선택 조회, 원본 메타데이터·불확실성 보존, DOM/native payload 차이, Query 완료와 렌더 성공의 구분은 현재 코드·공개 문서 대조에서 부정되지 않았다. 이는 읽기 전용 계약 대조이며 실제 helper 실행이나 전체 UI 부품 검증은 아니다.

## 4. 지금 구현에 들어가도 되는가

| 작업 범위 | 판정 | 조건 |
|---|---|---|
| 얇은 SKILL.md와 최초 3개 비교 과제 | **착수 가능** | 첫 View·폼 연결·native 전용 UI 선택으로 시작. 실제 호스트·후보 revision 확인 및 F5 적용 후 결과 기록 |

| inspect-ui 구현 | **아직 조건부** | F1 도입 조건 충족을 확인하고 F3/F7 계약을 고정한 뒤 착수 |

| 전체 계획을 새 구현자에게 무판단 인계 | **현재 미통과** | 위 Major 네 항목을 원문 실행 계획에 반영한 뒤 승인 |
| 지원·배포 준비 완료 발표 | **미완료** | 실제 두 호스트/발견 경로 검증, 정확한 패키지 조합, immutable 공개 ref, 소비·행동 결과 필요 |

권고 순서는 **보완 사항을 실행 계획에 반영 → 얇은 스킬과 기준선 비교 → 필요한 참조 → 근거가 있을 때 helper → 독립 소비·호스트 검증**이다. 이번 발견은 사용자가 이미 정한 D119–D121을 다시 선택해야 할 제품 분기가 아니다. 구현 담당자가 명시하고 검증할 기술 계약이다.

최종 전체 비교는 문구상 최소 10개 시나리오 × 2조건 × 3회 × 2호스트 = **120회**이며 초기 비교·재평가는 별도다. 초기 실험과 전체 배포 평가를 같은 작업 규모로 다루지 않는다. 실행 전에 해당 단계의 입력·모델·예산을 고정하고, 미실행을 성공이나 실패에 섞지 않는다.

9개 관점 모두 실제 FINAL_ANSWER를 받은 뒤 집계했다. 실패·재시도·미실행 단계는 없다. 별도 OSS 조사 에이전트는 읽기 전용 역할이라 파일을 만들지 못했으며, 주 작업자가 GitHub connector로 원문을 수집·고정했다. 이 조사 역할은 9개 Goldfish 수에 포함하지 않았다.

리뷰는 부모 대화를 전달하지 않는 `fork_turns:none`으로 수행했다. 파일시스템·호스트 AGENTS 지침의 격리까지 보장하지 않는다. 각 보고서에 실제 읽기 범위를 남겼으며, 호스트가 하위 도구의 전체 transcript를 제공하지 않아 읽기 영수증은 검토자의 실제 완료 응답에 근거한다. persona/standard/target hash 및 보존한 보고서는 [상태 기록](review_status.json)과 [산출물 검사](artifact_verification.json)로 연결한다.

제품 코드와 사용자 확정 명세는 변경하지 않았다. 원문 수정안은 위 조치로 제시했으며, 실제 수정 후 재검토를 이미 통과했다고 보고하지 않는다.
