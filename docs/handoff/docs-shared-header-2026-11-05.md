# 사이트 공통 헤더 적용

2026-11-05. 사용자가 홈·예제·Playground·문서의 헤더를 통일하고 문서에만 검색과 모바일 문서 메뉴를 추가하도록 요청했다. D111과 현재 명세 §3.4에 반영했다.

## 변경 범위

- `SiteHeader.astro`와 `header.css`가 모든 페이지의 로고, 주 메뉴, GitHub, 언어 전환, 화면 너비별 배치를 소유한다. 기존 홈 CSS에서 헤더 규칙을 옮겼다.
- 문서는 Starlight `Header` override를 통해 동일한 컴포넌트를 렌더링한다. Starlight의 바깥 header 안에서는 div로 렌더링해 header 중첩을 피한다. 기존 문서 전용 SiteTitle·SocialIcons override는 교체했다.
- 문서 검색은 기존 Starlight Search와 Pagefind를 사용한다. 모바일(<50rem)에서는 공통 헤더 아래 2.75rem 도구 행에 문서 메뉴·검색을 표시한다. 본문·사이드바·목차의 상단 오프셋도 같은 높이를 따른다.
- 문서의 언어 전환은 같은 경로의 번역 페이지로 연결한다. 홈·예제·Playground의 기존 대응 경로도 유지한다. 문서 전용 언어·테마 드롭다운과 중복 모바일 footer를 공통 탐색으로 대체했다.
- 모바일 메뉴는 실제 button의 `aria-expanded`와 화면의 열림 상태를 같이 갱신한다. 열려 있을 때 본문은 inert로 처리한다. Escape는 메뉴를 닫고 버튼으로 초점을 돌려주며, 메뉴 링크 이동과 데스크톱 크기로 전환할 때도 닫는다. 이 교체로 앞선 핵심 개념 작업에서 기록했던 Starlight 기본 메뉴의 접근성 속성 불일치가 해결됐다.

## 검증

- `apps/docs`에서 `astro build` 통과: 정적 페이지와 Pagefind 색인 생성. 런타임 패키지는 변경하지 않아 기존 빌드 출력을 사용했다.
- 새 모바일 메뉴의 TypeScript 스크립트를 추출해 strict DOM 타입 검사 통과.
- Ego Chromium의 정적 빌드 결과에서 8개 경로 × 6개 너비(320, 390, 768, 800, 1024, 1440px), 총 48개 조합을 검사했다. 경로는 영·한 홈, 영문 예제 목록, 한국어 상세 예제, 영·한 Playground, 영·한 개념 문서다. CSS 전환이 끝난 뒤 요청한 viewport 너비를 기준으로 헤더 겹침·가로 넘침이 없음을 확인했다. 문서에만 Search·문서 메뉴가 존재한다.
- 모바일에서 검색을 열어 `계산`으로 새 개념 문서를 찾았다. 한국어 개념 페이지에서 언어 링크를 눌러 같은 영문 페이지로 이동했고, 모바일 문서 메뉴에서 State 페이지로 이동했다. 메뉴 열림/닫힘, aria-expanded, 본문의 inert 해제, Escape 초점 복귀, 1024px 전환 시 닫힘을 확인했다.
- 홈과 문서의 데스크톱 스크린샷, 모바일 문서와 열린 메뉴 스크린샷을 검토했다. 로고·주 메뉴의 위치와 공통 행 높이·폰트가 동일하다.
- 문서 HTML 38개의 내부 링크·앵커 참조 1,264개 검사: 누락 0개. `git diff --check` 통과.
- 기존 빌드 경고(markdown 설정 deprecation, 큰 번들, 배포 site 미설정으로 sitemap 생략)는 유지된다. 배포와 커밋은 수행하지 않았다.
