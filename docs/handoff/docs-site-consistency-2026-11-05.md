# 사이트 디자인·사용 흐름 일관성 검토 — 2026-11-05

사용자 요청: 홈·문서·예제·플레이그라운드 전체의 디자인과 사용 흐름을 검토하고 어색한 부분을 수정한다. 현재 작업 트리의 공통 헤더·서체·간소화된 디자인·모션을 기준으로 검토했다.

## 범위와 완료 기준

| 대상 | 영·한 페이지 수 | 확인 내용 |
|---|---:|---|
| 홈 | 2 | 공통 헤더, 소개·실행 흐름·연동·예제 구간, 빠른 시작 진입 |
| 문서 | 34 | 시작하기 3·핵심 개념 9·가이드 4·레퍼런스 1씩, 제목·탐색·검색·코드 |
| 예제 목록 | 2 | 39개 실습의 단계별 탐색, 모바일 중복 목록 |
| 예제 상세 | 78 | 39개 × 2언어, 초기 실행, 편집기·결과·이전/다음 배치 |
| 플레이그라운드 | 2 | 빈 상태, 첫 실행, 수동 실행 상태, 언어 전환, 오류 복구 |

실제 콘텐츠 경로 118개 전부를 320px·1440px에서 탐색해 제목, 현재 메뉴, 가로 넘침, 페이지 탐색 및 예제 초기 실행을 검사했다. 화면의 시각적 검토는 홈 상·하단, 문서 개념·레퍼런스, 예제 목록·첫/마지막/다중 파일 예제, 플레이그라운드의 각 레이아웃과 상태를 대상으로 했다. 모든 문서 본문을 문장 단위로 재검토하거나 모든 예제의 모든 이벤트 분기를 테스트한 것은 아니다.

## 발견 사항과 수정

1. 모바일 예제 목록은 작은 내부 스크롤 메뉴와 본문에 같은 39개 목록이 중복됐다. 모바일에서는 본문 목록만 제공하고, 제목 아래 개념 표기를 같은 위치에 배치했다. 데스크톱의 단계별 사이드 탐색은 유지한다.
2. 모바일 예제 상세에서 하단 이전·다음이 사라져 결과를 본 다음 상단으로 돌아가야 했다. 결과 아래에 방향별 탐색을 배치했다. 데스크톱은 설명 영역 하단에 제공한다. 각 화면에서 실제 보이는 하단 탐색은 하나다.
3. 문서와 예제의 이전·다음 표현을 `PagePagination.astro`로 공유한다. 구분선·작은 방향 이름·페이지 제목·화살표·키보드 포커스를 통일했다. 목적지가 하나뿐이면 전체 너비를 사용해 긴 제목이 불필요하게 잘게 줄바꿈되지 않는다. 모션과 모션 감소 규칙도 공유한다.
4. 모바일 예제에서 숨겨졌던 자동 실행 안내를 표시한다. 다중 파일 버튼과 실행 안내/결과 이동을 두 행으로 분리해 작은 화면에서도 읽을 수 있다.
5. 빈 플레이그라운드에 사용자가 선택해서 실행하는 최소 Button 예제와 빠른 시작 링크를 제공한다. 기존 소스를 덮어쓰지 않고, 버튼은 빈 입력일 때만 표시한다.
6. 플레이그라운드에 수동 실행 안내와 `변경 사항 실행 전` 상태를 추가했다. 실제로 실행한 소스와 편집 중인 소스를 비교하므로 편집 후 이전 결과를 새 결과로 오해하지 않는다.
7. 같은 탭의 `sessionStorage`에 플레이그라운드 텍스트 초안을 보존해 언어 전환·재방문·새로고침 시 복원한다. 복원한 소스는 자동 실행하지 않는다. 저장소 접근 실패는 편집·실행을 막지 않으며 빈 입력은 저장값을 지운다. 잘못된 JSON을 모두 지우면 오류도 해제되어 첫 예제로 다시 시작할 수 있다.
8. 한국어 문서 검색의 지우기·결과 개수·빈 결과·더 보기와 코드 복사 문구가 영어로 남아 있었다. Starlight의 공식 i18n collection 확장으로 한국어를 제공한다. 한국어 건너뛰기 링크도 공통 사이트와 맞췄다.

홈의 제목 위계·구간 전환과 문서의 읽기 구조에서는 이번 검토 기준으로 추가 변경이 필요한 불일치를 발견하지 않았다. 기존 컴포넌트·서체·색상과 제품 설명 순서를 유지했다.

- 최종 Astro 정적 빌드 성공. Pagefind가 123 HTML 파일을 색인했다(콘텐츠 118 + 리다이렉트 4 + 404 1).
- 전체 `index.html` 122개에서 내부 링크·앵커 5,838개 검사: 누락 0.
- 전체 118경로 × 320/1440px = 236회 검사: 가로 넘침·제목 누락·예제 초기 오류 0. 모든 문서와 예제 상세에서 보이는 하단 탐색은 1개였다.
- 모바일 CSS 보완 뒤 예제 목록/상세 80경로 재검사, 태블릿 12경로 검사. 최종 빌드는 16개 대표 경로 × 320/768/1440px를 다시 검사했다. 총 관찰 376회, 발견 오류 0. 반복 관찰을 서로 다른 페이지 수로 세지 않았다.
- 예제 39개 × 영·한 전체 초기 실행 성공. 다중 파일 예제에서 `코드에서 보기` → inputs.json 선택·포커스, 잘못된 JSON → 이전 정상 결과 유지, 코드 초기화 → 복구 확인.
- 홈 주 CTA → 빠른 시작 → 같은 예제 실행, 모바일 예제 목록 → 첫 예제 → 결과 → 다음 예제 이동 확인.
- 모바일 문서 메뉴 열기/Escape 닫기, 영문·한국어 State 검색 결과 확인. 한국어 검색은 `State 검색 결과 14개`, 일치하지 않는 검색어는 한국어 빈 결과 메시지, 코드 복사 버튼은 `코드 복사`로 표시됨을 확인.
- 플레이그라운드 첫 예제 실행, 변경 미실행 표시, 영문 전환 후 한글·영문·기호가 포함된 초안 복원, 복원 후 미실행, Ctrl/Meta+Enter 실행, JSON 오류·빈 입력 복구를 확인.

## 제한과 남은 이슈

- 프로젝트 전체 TypeScript 검사와 tsconfig 기반 svelte-check는 `node_modules/@astrojs/starlight/utils/i18n.ts:94`의 `astroI18nConfig.routing` possibly undefined (TS18048) 한 건으로 실패한다. 변경한 컴포넌트의 오류로 보고된 것은 아니며 의존성을 임의 수정하거나 검사를 끄지 않았다. 위 Svelte 단독 검사와 빌드 성공을 전체 타입 검사 통과로 해석하면 안 된다.
- 빌드의 기존 markdown 설정·큰 청크·site 미설정 sitemap 경고는 별도 배포/빌드 설정 범위다.
- Chromium의 반응형 뷰포트로 확인했으며 실제 모바일 OS 키보드/터치 전체 테스트를 대체하지 않는다. 저장소가 차단된 환경은 코드의 예외 처리로 대비했지만 이번 브라우저에서 별도로 재현하지 않았다.
- core/renderer/UI 패키지의 공개 계약과 지원 범위는 변경하지 않았다. 배포·커밋은 수행하지 않았다.
