# Viewstem 워크스페이스 성능 점검

기준 리비전은 `bf85152`다. Apple M2, macOS 15.8, Node 22.23.4와 Playwright
Chromium에서 같은 예제를 순차 실행했다. 전체 비교는 예제별 예열 1회와 측정
3회, Core 및 UI의 변경별 비교는 예열 2회와 측정 7회를 사용했다. 실행 명령과
구간 정의는 [벤치마크 안내](../../bench/README.md)에 있다.

| 대상 | 시나리오 | 범위 |
| --- | ---: | --- |
| Core | 26 | 등록과 참조, State와 Derived, 값 검증, CEL, URL, Grid, Action, HTTP, Query, View |
| DOM | 8 | 기본·커스텀 연결자, 슬롯과 키 유지, 이벤트, 해제, DOM·PostCSS 스타일 스코프 |
| Svelte | 6 | 어댑터 수명, 슬롯, 혼합 렌더링, 호스트 소스 교체 |
| UI | 76 | 66개 패밀리 마운트와 대형 선택기·테이블·폼·달력·메뉴 동작 |
| 문서 앱 | 123 | 영어 레슨 39개와 컴포넌트 페이지 66개, 한국어·모바일 예제, 검색·워크벤치·플레이그라운드 |

기준본과 수정본에서 239개 시나리오의 동작 검증을 통과했다. 독립 검토 후
DOM 키 유지, 브라우저 예외, 메뉴 열림, 정렬 순서, 필터 결과를 확인하도록
벤치를 보강하고 관련 14개를 두 빌드에서 다시 실행했다.

| 변경별 측정 | 기준 중앙값 | 수정 중앙값 |
| --- | ---: | ---: |
| Query Join 3,000 × 3,000행 | 49.7–60.0ms | 0.58–0.78ms |
| Type 100개 등록 및 순차 갱신 | 164.8–183.4ms | 11.4ms |
| State·Derived를 가진 반복 인스턴스 200개에서 공유 상태 3회 갱신 | 104.6–108.2ms | 27.3ms |
| NativeSelect 옵션 953개 마운트, Core 변경을 양쪽에 적용 | 56.2ms | 49.4ms |
| NativeSelect 옵션 953개에서 선택, Core 변경을 양쪽에 적용 | 55.7ms | 52.0ms |

- Join은 반대쪽 행을 키로 인덱싱한다. 복합 키의 타입 구분, null 처리, 중복
  매칭 순서와 오른쪽 필드 우선순위를 확인했다.
- Registry는 검증 한 번에 Type 목록을 한 번 만들고, 내부에서 깊게 동결한
  정의의 스키마 컴파일 결과를 재사용한다. 가변 입력 스키마는 호출 시점의
  값을 사용한다.
- Derived 계산을 같은 연결로 다시 묶을 때 의존 그래프를 순회하는 작업을
  생략한다. 연결 변경 시 순환 검사와 실패한 변경의 복구를 확인했다.
- UI는 관리 대상 속성을 한 번 모으고 목록이 바뀔 때 DOM에 반영한다. 입력
  속성이 빠지면 같은 노드에서 기존 속성을 제거한다.

시스템 작업이 겹친 구간에서는 문서 앱의 표본 편차가 컸다. 전체 비교에서
중앙값이 3ms와 20%를 모두 넘게 증가한 문서 사례 16개를 재측정했고, 모두
이 기준 안에 들었다. 수치는 로컬 DOM 및 렌더러 완료 시점, 고정된 모의 HTTP
데이터, 명시한 예제 규모를 기준으로 해석한다.

Core 1,216개, DOM 25개, Svelte 57개, UI 46개의 테스트를 통과했다. Core의
Chromium 및 배포 패키지 검증과 DOM·Svelte 패키지 소비자 검증도 통과했다.
문서 앱은 빌드, 타입 검사, HTML 327개와 링크 36,588개 검사를 통과했다.
