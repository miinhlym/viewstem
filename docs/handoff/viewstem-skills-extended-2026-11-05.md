판정: **공식 첫 배포는 보류한다.** Codex의 공통 스킬 발견과 소비 작업 검증은 확보했지만, 현재 개발 라이브러리에서 투영 불일치가 재현됐고 Claude Code 실행·다른 호스트 발견 경로·공개 immutable ref는 아직 검증되지 않았다. Claude Code는 사용자 지시에 따라 준비만 유지했다. 제품 코드나 공개 발행은 이번 작업에서 변경하지 않았다.

최종 후보는 [공통 스킬 B3](../../skills/viewstem/SKILL.md)다. 배포 파일은 여전히 본문·Codex 표시 정보·두 호스트 안내의 4개이며 추가 참조나 조회 helper는 만들지 않았다. [원래 초기 비교](viewstem-skills-initial-2026-11-05.md), [확장 실행 계약](../designs/viewstem-skills-extended-2026-11-05.md), [전체 측정·산출물](../../skills/tests/extended-results.json)을 구분한다.

B2의 실제 스킬 본문 읽기는 대상 과제 **27/27**, 비활성화 과제 **0/6**이었다. Viewstem 이름이 없는 기존 폼 수정도 3회 모두 본문을 읽었다. 비활성화 과제의 코드·응답 전체에서 불필요한 Viewstem 도입이나 조언은 발견하지 못했다. 파일 경로에 프로젝트 이름이 나타난 것을 조언으로 세지 않았다.

비활성화 결과는 실제 도구 출력에서 본문을 읽은 증거와 산출물을 기준으로 한다. 호스트의 내부 선택 상태 전체를 계측한 것은 아니다. B3는 description·Codex metadata·호스트 안내를 바꾸지 않아 같은 발견 조건의 증거를 유지한다.

## 관찰에 따른 B3 보완

1. B2 폼 r1이 `rg`로 패키지의 JSON까지 재귀 검색해 한 명령에서 1,048,607 bytes를 출력했다. 압축된 지원 JSON에서는 `head`가 바이트 양을 제한하지 못한다. 본문에 이 파일을 일반 재귀 검색에서 제외하고 `JSON.parse` 후 필요한 ID·키를 선택하도록 명시했다.
2. B2 폼 r3은 Query 성공과 State 값 변경 뒤에도 표시되지 않았다. `View.subscribe`에서 표시용 State를 동기적으로 갱신하면 State와 노드 투영이 달라지는 현상을 public core API와 실제 브라우저에서 재현했다. 표시 값은 Query에서 선언적으로 연결하도록 권고하고, 이 개발 산출물의 재현된 제한임을 명시했다.

두 번째 현상은 공개 API 오용으로 단정할 수 없다. 구독 쓰기를 금지하는 계약을 찾지 못했으며, 제품 수정도 하지 않았다. 직접 Query 바인딩 및 microtask 지연 대조가 통과해도 원래 실패를 통과로 덮어쓰지 않는다. [재현·회피 방법·제품 후속 조건](view-subscription-projection-2026-11-05.md)에 따로 기록했다.

B3는 폼·native·버전 진단·View 교체의 4개 관련 과제를 각 3회 다시 평가해 **12/12 통과**했다. 모든 실행에서 실제 B3 본문을 읽었고, 앞서 관찰한 1MB 지원 JSON 출력은 재발하지 않았다. 폼·View 교체 6건은 독립 의미 검토도 통과했다. 이 12회는 동일한 A 결과를 기준으로 하는 수정 후 검증이며 처음부터 정한 독립 조건이 아니다. B3 전체 11개 과제를 새로 실행했다고 주장하지 않는다. 최종 개별 결과와 내용 hash는 결과 JSON의 `arm: B3`를 따른다.

## 비용 지표와 해석

기본 A/B2 각 33회에는 실패한 실행도 포함한다. 시간은 모델 실행 구간만 더한 것으로 fixture 복사·외부 채점 시간과 구분한다.

| 지표 | A | B2 |
|---|---:|---:|
| 모델 wall time 합계(초) | 2,758.934 | 2,630.050 |
| 명령 실행 호출 | 365 | 366 |
| 명령 출력 bytes | 3,918,830 | 3,024,110 |
| input tokens | 15,391,278 | 14,862,168 |
| 위 input 중 cached | 14,319,744 | 13,777,280 |
| output tokens | 82,853 | 76,900 |

**성공률 향상이나 일반적인 생산성 개선은 입증되지 않았다.** 기준선은 이미 모두 통과했고 비용 차이는 작거나 과제마다 반대였다. 각 조건 3회, 순서 교대, 일부 병렬 실행과 캐시가 섞인 관찰이므로 인과적 속도 개선으로 해석하지 않는다. bytes를 tokens로 환산하거나 cached를 input에 더하지 않았다. B3는 실제 실패·과도한 읽기에 대한 구체 보완으로 채택한다.

## 검증 방법과 평가기 수정

- Codex `0.160.0`, `gpt-6.1-terra/high`, 새 ephemeral 세션, 최대 360초·명령 50회. 관리 runner와 외부 검사 Node는 `v22.21.1`이다. 모델의 shell에서는 Node `v24.19.0`도 관찰됐다. 양쪽에 같은 도구 환경을 제공했지만 모든 자식 명령의 Node 바이너리를 고정한 성능 실험은 아니다.
- 초기 평가와 같은 세 개발 tarball hash 및 Svelte `5.57.3` 사용. core-only는 manifest·lock·설치 트리에서 Svelte 의존성을 제거하고 strict NodeNext를 검사했다.
- 브라우저 과제는 타입·번들·실제 Chromium 행동·정리를 확인했다. 진단 과제는 실제 설치 manifest·공개 타입·CEL 파일을 확인하며 실행/타입 검사를 적용하지 않는다. 일부 모델 내부 browser check는 localhost 바인딩 EPERM으로 제한됐다. 모델이 보고한 제한과 외부 판정자가 실제 실행한 결과를 분리했다.
- 실제 생성 코드의 State/Action/Query·소유권·native 의미와 최종 설명을 검토했다. 핵심 6개 범주 A/B2 36건은 독립 검토자가 35 PASS/알려진 1 FAIL로 확인했다. 나머지 범주는 주 작업자가 검토하고 유효한 초기 검토 증거를 재사용했다.
- 다른 개인 스킬은 양쪽에서 사용 가능했다. 실제 trace에서 원 저장소 checkout을 읽은 명령은 관찰되지 않았지만 전체 파일시스템 격리를 주장하지 않는다.

비교 도중 평가기도 보완했다. 실패한 `cat`이나 단순 경로 조회를 본문 읽기로 세지 않도록 성공한 본문 출력과 접근 기록을 분리했다. 기존 결과의 존재만으로 재사용하지 않고 같은 run ID의 덮어쓰기를 거부한다. 채점은 별도 프로세스에서 제한 시간을 적용하며 생성된 Node 코드는 10초 제한을 적용한다. 진단 evidence는 공개 export 문자열만으로 인정하지 않고 실제 설치 파일로 해석한다. 영향을 받는 24개 산출물은 최신 검사기로 재채점했고 원래 결과도 보존했다.

반복 목록 검사기는 모델 실행 전에 DOM 상태 보존에서 실제 행별 core State 확인으로 보강했다. 정상·오류 fixture 검증을 거쳤으며, 기존 형식 검사나 경로 정규화의 실패를 모델 실패로 계산하지 않았다.

## 설치·준비·배포 경계

Codex의 별도 프로젝트 설치에서 `$viewstem` 명시 호출, 상대 경로의 Codex 안내 읽기, Node로 실제 파일 hash·앱 manifest 확인을 수행했다. B2 설치 → B3 교체 → B2 되돌리기를 각각 새 세션에서 확인했다. 세 단계 모두 올바른 revision을 읽고 앱 파일을 변경하지 않았다. 최초 검사기가 Node 22만 허용해 Node 24를 오판한 건은 동일 trace를 Node ≥22 계약으로 재채점했다.

B3의 네 파일을 ZIP으로 만들고 압축 해제 결과의 동일성을 확인했다. 이는 로컬 검토용 산출물이며 공개 설치 ref가 아니다. archive·파일별 SHA-256은 결과 JSON에 기록한다.

Claude Code는 11개 과제의 A/최종 B3 입력·폴더·호출 초안 **22개를 준비했다**. 모델 및 실제 CLI 설정은 미지정이고 `not_run(reason=user_requested_preparation_only)`로 남겼다. CLI 설치·로그인·모델 호출은 없다. 준비된 공통 파일은 실제 B3와 같은 hash로 검사했다.

| 배포 조건 | 판정 |
|---|---|
| 공통 4파일과 Codex 프로젝트 발견·명시 호출·교체·되돌리기 | 확인 |
| Codex 행동·불필요한 활성화 | 위 기본 비교와 B3 관련 과제 결과 범위에서 확인 |
| 현재 개발 라이브러리의 투영 불일치 | **미해결**. 회피 지침이 제품 수정은 아님 |
| Claude Code 실제 실행 | 사용자 지시에 따라 미실행 |
| desktop/계정 업로드/클라우드별 발견 | 미검증 |
| 정확한 공개 릴리스 조합과 immutable 배포 ref | 미확정·미발행 |

따라서 로컬 Codex 개발 후보의 검토 자료는 갖췄지만, 두 호스트를 처음부터 지원한다는 공식 첫 배포의 완료 조건은 충족하지 않았다. 이 판단을 피하려고 지원 목표를 Codex 전용으로 바꾸지 않는다.

재현 runner는 [run-extended.mjs](../../skills/tests/run-extended.mjs), 수집기는 [collect-extended.mjs](../../skills/tests/collect-extended.mjs)다. 결과 JSON에 raw trace hash, 실제 생성 코드, 프롬프트 hash, 판정·재채점, 준비 내역, 독립 검토와 런타임 재현을 남겼다. raw 앱·trace·tarball은 기록된 로컬 임시 workspace에 보존했으며 그 경로의 장기 존속을 전제로 하지 않는다.
