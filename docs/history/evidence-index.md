- **U09 · integer의 JS 안전 정수 범위:** 2026-10-29 현재 프로젝트 대화에서 어시스턴트가 integer를 -9,007,199,254,740,991부터 9,007,199,254,740,991까지만 허용하고 범위를 벗어나면 오류로 거절하는 안을 제안했다. 범위 밖에서 서로 다른 정수가 같은 JS 숫자로 읽힐 수 있으므로 자동 반올림·문자열 변환을 하지 않고 큰 정수 식별자는 처음부터 문자열로 선언해 전달하도록 설명했다. 사용자가 “그래. integer는 JS 안전 정수 범위만 허용하는 기준으로 문서에 반영하고, 다음으로 결정할 사항 하나만 설명해.”라고 수락했다. [현재 값 계약](../spec/10-value-contracts.md#integer의-안전-정수-범위)에 반영한다. number의 소수 정밀도, CEL 내부 연산과 BigInt 지원까지 확정한 승인은 아니다. 현재 프로젝트 대화의 결정이고 과거 transcript의 승인으로 소급하지 않는다.

- **U10 · number의 binary64 표현과 자동 반올림 금지:** 2026-10-29 현재 프로젝트 대화에서 어시스턴트가 number를 JS Number와 같은 64비트 부동소수점으로 다루고 core가 자동 반올림하지 않는 안을 제안했다. `0.1 + 0.2`의 결과를 `0.30000000000000004`로 유지하며, 서비스의 JS 숫자와 표현을 맞추고 필요한 반올림은 계산·표시 단계에서 명시하도록 설명했다. 사용자가 “그래. number는 JS Number와 같은 64비트 부동소수점을 사용하고 자동 반올림하지 않는 기준으로 문서에 반영하고, 다음으로 결정할 사항 하나만 설명해.”라고 수락했다. [현재 값 계약](../spec/10-value-contracts.md#number의-표현과-자동-반올림-금지)에 반영한다. binary64 자체의 근사 표현을 없애거나 정확한 십진 연산을 보장하는 결정은 아니다. -0 처리·구체 직렬화·CEL 어댑터·반올림 함수 카탈로그 전체까지 확정한 승인은 아니다. 현재 프로젝트 대화의 결정이고 과거 transcript의 승인으로 소급하지 않는다.

- **U11 · 음수 0을 양의 0으로 정규화:** 2026-10-29 현재 프로젝트 대화에서 어시스턴트가 core가 값을 받아들일 때 -0을 0으로 정규화하고 기존 0에 -0을 써도 변경으로 보지 않는 안을 제안했다. JS의 JSON 직렬화와 Set·Map 비교 기준에 맞추되, 0의 부호에 의미를 두는 특수 계산의 구분은 보존하지 않는 선택이라고 설명했다. 사용자가 “그래. -0은 0으로 정규화하는 기준으로 문서에 반영하고, 다음으로 결정할 사항 하나만 설명해.”라고 수락했다. [현재 값 계약](../spec/10-value-contracts.md#음수-0의-정규화)에 반영한다. 작은 음수의 자동 반올림이나 문자열 숫자 변환, CEL 내부 중간 연산·구체 직렬화 전체를 확정한 승인은 아니다. 현재 프로젝트 대화의 결정이고 과거 transcript의 승인으로 소급하지 않는다.

- **U12 · 세부 계약 판단 위임과 값 검증 기본 규칙:** 2026-10-29 현재 프로젝트 대화에서 사용자가 “너가 결정해도 될 정도로 당연한 것들은 다 결정해버려도 될 것 같은데.”, “이렇게 하나하나 물어봐서는 전혀 안 끝날 것 같아서 말야.”라고 지적하며 세부 판단을 위임했다. 이에 따라 어시스턴트가 기존 값 모델을 유지하는 범위에서 미지원 데이터 값·순환 구조 거절, 비순환 공유 허용, 스키마 검증의 자동 보정 금지, 수용 순서, 유한 숫자 정확 비교·객체 속성 순서 무시를 [공통 규칙](../spec/10-value-contracts.md#값-검증의-공통-기본-규칙)으로 일괄 선택했다. 이는 사용자에게 각 규칙을 개별 승인받은 기록이 아니라 명시적인 위임에 따른 담당자의 설계 결정이다. [논의 기준](../handoff/open-contracts.md#세부-판단의-위임과-논의-기준)에 따라 기존 의미를 보존하는 구현 선택은 담당자가 구체화하고, 서비스 동작·호환성·지원 범위를 실질적으로 바꾸는 미결만 별도 논의한다. 구현 보류는 유지하며 코드 구현·공개·배포 승인으로 확대하지 않는다. 현재 프로젝트 대화의 결정이고 과거 transcript의 승인으로 소급하지 않는다.

- **U13 · 남은 계약 전체의 위임 판단과 중요 논의 분리:** 2026-10-29 사용자가 “그래. 남은 계약도 네가 결정할 수 있는 건 문서에 반영하고, 내가 결정해야 할 중요한 논의 사항 가져와.”라고 요청했다.
